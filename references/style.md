# 贴近用户自己的说话方式

优先用用户当前明确要求和纠正，其次参考本人已发出的类似场景消息，再看经确认的旧简报。草稿、助手选项、模拟台词、转发和对方的话不作为用户实发样本。临时指定“这次正式点”只约束这次。

从几条可比消息里提取具体习惯：常用词和称呼、句长、几条分开发、标点与表情、接话和开玩笑的方式、表达关心或异议的直接程度。可以记“通常一句一个点、少用表情、用短反问接熟人的梗”；如果只有一条，标样本有限，先用普通微信口语。严肃谈事和朋友闲聊可能有不同风格，优先匹配当前语境。

对方的习惯另记，用来调整话题、节奏和回复负担。对方爱用叠词或表情，不代表用户也这样发。昵称、方言、脏话、拼写习惯和亲密动作只按已知的用户表达与当下范围选择。

## 自然度检查

- 读一遍，确认像即时接话，顺嘴且意思明确。有人会短答，也有人会认真说几句；由场景决定。
- 通用开头如“哈哈”“哇”“可以啊”只在自然表达真实反应时保留。换掉可以贴到任何对话的起手式，用眼前一个具体细节起句，也可以直接作答。
- “终于”“今晚”“盼了很久”会带入等待经历或具体时间。只有上下文支持时才用，单凭“我要去看”可以接喜悦或兴趣。
- 删掉分析式复述、强行接梗、活动宣传口吻、堆叠客套、每句一个反问和没有依据的昵称。日常接话可以说“还在改啊？”；需要道歉、协商或明确拒绝时说清具体的事。
- 不用表情、语气词、错字或故意省标点来表演口语。用户要求保留原句时只改指出的问题；已有边界、承诺和重要事实照实保留。

用户的口气偏好如何沿用或更正，见 [反馈](feedback.md) 和 [记忆](memory.md)。
