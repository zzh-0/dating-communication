# 邀约、关系确认与维护

已有明确沟通目标后，按 [策略](strategy.md) 核对当前时机与边界，再使用下面的具体安排。

## 把兴趣落成一次可选择的安排

已有共同话题和来回交流时，可以直接邀请，不必等到“确定喜欢”才开口。先看对方限制的是时间、活动还是见面本身；前两者若主动给了替代，就正常协调。拒绝本次安排不等于拒绝整个关系，但不能换包装反复劝同一安排；明确不想见或别再约时停止邀约。

一次邀请包含：**活动或理由＋一个具体时间范围＋可调整的选择空间**。地点选择考虑双方出行、预算与活动偏好；缺事实时给可填写的方案，不虚构某家店、营业时间或演出。

例如，双方已聊过那个展、用户想周六去，可以直接说：“周六一起去看那个展？”答应后再确认几点、在哪碰面，不先把时长、费用和所有选择都塞进邀请。“周六还是周日”用于协调已同意见面的人，不用于封锁拒绝。

第一次见面通常先安排公共、方便各自离开的活动。可准备一个双方都愿意才继续的选项，不把转场、进入车内或私密空间当作流程要求。活动的目的是一起体验与了解，不是让对方接受下一步接触。

| 对方反馈 | 下一步 |
| --- | --- |
| 答应并讨论细节 | 确认时间、地点和实际安排，不追加长篇试探 |
| 时间或活动不合，但给了替代 | 直接接住可行替代；无需再分析好感或先发退场话术 |
| “有空再说”等模糊回应 | 可轻量确认一次，或把选择交还；不追着索要日期 |
| 多次婉拒且没有替代、持续回避 | 停止邀约，不靠礼物、竞争者或施压争取 |
| 明确不愿与用户见面，或要求别再邀约 | 停止邀约；无需逼对方解释充分理由 |

费用超出预算时，直接说：“这家有点贵，换一家吧？我这次想控制在三百左右。”金额按用户真实预算调整；确实要商量分担时再说，不自动把分担也塞进每次表达。不把不同消费偏好直接诊断成拜金，不将消费兑换成亲密义务。

## 约会后的表达

想继续，可以指出一个真实愉快片段，再表达下次见面的愿望；不要求当天必须告白或完成身体升级。若没有继续的意愿，帮助用户清楚礼貌地说出来，不编造前任、家庭事件或长期出差作挡箭牌。

身体接触单独确认。一次邀约、调情、拥抱或之前的许可，不等于同意新的接触。对方拒绝、躲开或明显不适时停下；不通过反复尝试、换场所或“既然都来了”绕过。

## 关系身份与期待需要谈清

暧昧、见面多次、发生亲密行为、互赠礼物都不能由助手替双方定义为恋人或排他关系。准备度不一致时，帮助用户直接表达自己的期待并询问对方，而不是设计一个让对方无法拒绝的表白。

可按用户实际意图改写：“我挺喜欢你的，想跟你在一起，你怎么想？”若用户关心的是是否还与别人约会，就把那件事问清，不让一句泛泛的表白代替所有约定。对方不确定时，讨论双方能接受的相处方式；用户也可以因目标不同选择退出，不无限等待“攻略成功”。

## 稳定关系：从需要落到可执行约定

先区分：用户想给什么、对方需要什么、各自能持续做到什么。针对联系频率、陪伴、费用、公开程度、私人空间等具体事项协商，不把一种习惯当成爱的唯一证明。

例如，用户白天忙无法常看手机、愿意晚上聊，可以说：“白天上班没法一直回消息，晚上有空了再聊，行吗？”确有固定时间需求，再具体商量，不一开始就做成一段需求访谈。表达须符合用户实际能力，别承诺每天做到却无法兑现。双方偏好未必相同，可以轮流安排、各自活动或重新协商。

发生冲突时选择所需步骤，不强行套齐模板：

1. 说清具体事件与影响，避免“你总是、你从不”和人格标签。
2. 有真实过错就具体承认，停止相应行为；解释背景不能取消责任。用户未提供原因时，只说已知行为与影响，不替其补写“只是想活跃气氛”等动机。
3. 说出自己的感受、需要或限制，提出一个可执行请求，听对方的版本。
4. 情绪过高需暂停时，说明自己要暂停，并在双方愿意时约定再谈；不用失联惩罚。
5. 回到实际改变与兑现，不用一次道歉要求立即原谅。双方持续无法接受彼此需求时，也可以结束关系。

对方被玩笑伤到，可以先说：“刚才那个玩笑不该说，对不起，以后不拿这个逗你了。”需要解释具体事时把事说清，不接“你太敏感”，也不把道歉包装成调情。是否继续讨论由当下状态决定。

边界可以温和也可以直接；不需要反复举证才成立。用户要分开时，帮助其明确表达，不建议用伤害、冷漠或触碰底线逼对方先提分手。
