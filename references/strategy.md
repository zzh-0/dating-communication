# 沟通策略决策

先定**这一步要做成什么**，再选措辞。决策依据是用户当前目标、对方这句在做的事、关系模式、当前互动、未完事项和限制。涉及身份、冷淡或推进时参照 [关系建模](relationship.md)；读不清这句在回什么或想要什么时参照 [意图](intent.md)。

1. **处理行动条件。** 有明确停止联系或拒绝就按范围停。正在紧张或误会时先澄清、道歉、给空间，必要事务按原约定处理。已说清的安排与明确问题先回答。
2. **选当前首要目标。** 跟对方一起高兴、听一会儿、给一条所问的意见、接共同话题、确认安排、表达心意、修复或结束当前话轮都可以成为目标。目标依据一两条已知证据，日常回复不必展示分析过程。
3. **选择几种实际可行的做法。** 可改变对话继续的方式、需要的投入或何时行动。三条应有真实差异；边界窄、事实缺失或用户限定原意时减少候选。进入 [生成](generation.md) 前就能说清每条的目的与适用条件。

| 情况 | 优先考虑 | 有依据才加入 |
| --- | --- | --- |
| 刚认识，分享一件生活小事 | 回应具体内容、轻问兴趣、简单祝愿 | 用户有意且已有来回交流和具体共同兴趣时，可以轻量邀请一次 |
| 朋友，话题双方熟悉 | 分享快乐、接已有梗、回访真实共同经历 | 承接已有讨论或安排；尊重朋友定位 |
| 暧昧，有双向互动，用户愿意继续 | 回应已有调情、留一个轻松后续、延续共同兴趣 | 可就共同话题发出一次具体邀约；双方都有意参加时再协调细节 |
| 恋人，已有明确分工或约定 | 共庆、关心具体需要、处理已有安排 | 亲昵称呼和实际帮助依据用户习惯与可做到的事 |
| 只是吐槽或明确想被听见 | 接住一件事，允许对方继续说或去休息 | 对方求意见或同意讨论方案时给建议 |
| 误解或不满 | 核对一句事实、承担具体过错、安排双方愿意的再谈时机 | 已有关系共识时也先解决当前争议 |
| 近几轮参与低、对方忙或已经收尾 | 完整回答必要信息，低负担收尾或暂不回复 | 有真实待办时发一条确认；不以重启聊天为由重复邀约 |

同一消息可对应不同目的。演唱会分享可以在刚认识时了解喜欢的歌手，在朋友间接上已知共同歌单，在彼此暧昧且已经约好交换现场视频时自然续上这件事，在伴侣已有接送约定时确认散场安排。没有这些上下文就从分享本身接；有紧张、暂缓或限制时先处理眼前情况。

用户明确想保持现状、只想关心一下或结束关系时，策略围绕其目标。推进优先考虑已有往来、用户愿意以及对方对相应方向的实际反馈。首次邀请与协调已同意的安排分别处理，具体做法见 [邀约与关系维护](relationships.md)。若选择等，说明什么变化才值得重看，例如对方给了替代时间、用户有一件真实待办。尊重用户选别的说法或自己决定。
