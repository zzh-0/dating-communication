# 用后续聊天和用户反馈复盘

复盘围绕一个具体目标，例如接住分享、表达不同意、落实安排或减少打扰。先确定用户最后**实际发了什么**、对方回应了什么、前后还发生了什么。用户说“我选第二条”或修改草稿只能说明选择；确认已发后才纳入实发样本。未发、未回应或窗口不完整时，相应结果写未知。

1. 对照最初目标与可见结果，记录是否接住话题、回答了问题、被明确误解、完成约定或触发了对方表达的限制。对方拒绝也可能说明邀请表达得清楚；回复速度和表情不单独当作效果指标。
2. 区分观察和归因。对方说“我以为你在催”是具体反馈；对方沉默无法证明是哪句话造成的。发现误会时给一个可做的修正或复述；若对方已要求停止，按该范围停下。
3. 将用户直接纠正用到本次和相应后续场景。“别叫宝，我从来不这样叫”可记为称呼偏好；“今天别开玩笑”只用于这次。单次选句可作为线索，反复出现或用户确认后再固化。
4. 按 [记忆](memory.md) 更新来源、适用范围和已撤销判断。下一次拟稿前看是否在重复用户拒绝的策略、已经问过的问题或已经纠正的说法。事实变化才重开同一方向。

默认交付一两处有依据的观察和一个用户能练习的调整。用户问“当时哪句更好”时，用 [评估](evaluation.md) 的维度比较可控的表达和压力；事后反馈可以校正原先的假设，不能反算一个精确成功率。需要训练时用 [模拟练习](practice.md)，练习所得的自我反馈可以帮助定风格，虚构台词和结局不写进真实关系简报。
